Personal Budget Optimiser

I decided to build a personal optimiser for my budget using the skills i picked up as a backend engineer, and the theoretical training in maths i have.
Three main needs inspires this: 1. I don't trust conventional software with my financial information, I even scrub PII locally and containerise. 2. A project to showcase my software engineering, and analytical capabilities. 3. Conventional software lacked the specificity and often times the simplicity of my needs.
I wanted to use: - Statistics to predict budget overruns - Applied Maths to reallocate my budget
To that end I divided my income into broad categories then assign an initial budget to each category based on what I felt was right.
I would each month get a monthly statement then via RESTApi give my backend how much a spent in that month per category, which would save to a database.
Initially I have only 6 months worth of data, so I elected to use a monty carlo simulation to get more data and make a prediction, it worked really well from feelings point. I called a GET, that would get a date range in the DB, and hand the user the prediction based on category
I think that would work good enough, but I also want to experiment with Machine Learning, since it could do bot prediction and optimising.
I planned to apply ML not on reported monthly category amounts, rather use ML to categorise, then again to predict.
Categorise: I initially wanted an simple approach, using logistic regression to determine yes/no it belongs to 'Groceries'
A transaction would be ran for each category putting it at risk of being assigned to more than one category. I could fix that by saying if it already belongs to one, do not assign to another, but as a backend engineer I refuse to solve an ambiguity to what category it ultimately belongs to.
Instead the ML would use Multinomial LR to decide which category to put a transaction.
though I encountered a problem Statements were only available in pdf form. I didn't trust all these tools to convert to csv, so I containerised python pdfplumber. And had AL make a simple flask python backend to communicate with it. It didn't work out, I am still investigating.
Prediction. Prediction could use a simple logistic regression could be used to predict a budget overrun since it is a binary outcome.
Back to analytics. On the applied maths side, Linear programming where the weights would be determined by the prediction statistics would be used to optimise the budget.
and Back to the tech stack. I used java springboot as the coordinating backend, and I choose a backend architecture to call the python scripts, cause it is easy to containerise, and separate my frontend from my mathematics but still share a db.
I eventually want to self-host this to it gives the opportunity to tailor the frontend to the device i am using it on, like phone seperate FE to computer while still using the same service, and allows adding jwt authentication for privacy.
